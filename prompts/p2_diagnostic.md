## 你需要分析的维度

请从以下角度逐一分析：

1. **失败定位**：是代码实现问题（Phase A 失败）还是方案本身问题（Phase B 失败）？
   - Phase A 失败：可能是工程问题——环境配置、依赖版本、数据格式、代码 bug
   - Phase B 失败：可能是科学问题——假设错误、方案有漏洞、超参数不当

2. **假设是否成立**：论文前体的核心假设是否被实验结果否定？如果 loss 持续发散或精度极低，可能是假设本身有问题。

3. **实验设计是否合理**：
   - 数据集是否太小/太简单/太难？
   - 超参数（学习率、batch size 等）是否在合理范围？
   - 评估指标是否正确反映主张？

4. **服务器/环境因素**：
   - 是否可能是 GPU 内存不足（CUDA OOM）？
   - 是否是依赖未正确安装？
   - 是否是数据集无法获取？

5. **改进建议**：给出 2-3 条**具体的**改进方向：
   - 如果是工程问题：调整环境、修复依赖、简化实验设置
   - 如果是方案问题：换前体、调整假设、缩小实验范围

## 输出格式

直接输出 Markdown 格式的诊断报告（不要 JSON），包含：
- 开头总结（1-2 句话点明最可能的根因）
- 分维度分析
- 具体改进建议（标注优先级）
